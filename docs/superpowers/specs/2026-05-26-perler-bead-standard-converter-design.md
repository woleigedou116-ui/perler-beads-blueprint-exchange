# 拼豆图纸颜色标准转换工具：首版设计规格

## 1. 项目目标

为拼豆玩家提供一个本地运行的网页应用，将使用一种颜色标准的电子图纸转换为目标标准的可用图纸。

首版聚焦 `MARD -> COCO` 转换。用户上传带规则网格、格内或图例中存在可读 `MARD` 色号的图片后，系统结合文字识别和颜色取样生成可校对的转换结果，并导出：

- `MARD -> COCO` 转换清单与目标色号用量统计。
- 统一版式、干净重绘的 `COCO` 完整网格图纸。
- 原图叠加识别结果与疑点标记的检查图。
- 可重新打开、继续校对的本地项目文件。

产品长期方向是支持图纸编辑、更多品牌转换、Excel 导入和更宽泛的图像来源，但这些不应扩大首版识别范围。

## 2. 用户素材与已验证假设

当前素材位于：

- `拼豆样例图/`：4 张待转换图纸样例。
- `标准对应转换/mard和coco/`：2 张 `MARD` 与 `COCO` 对照资料。
- `标准对应转换/多种标准对应/`：10 张包含更多品牌的对照资料。

对代表样例的观察：

- 待转换图片均为规则网格电子图纸，而非实物拼豆照片。
- 网格格子中存在如 `H7`、`H2`、`F14`、`D5` 等来源色号文字。
- 图片可能带有水印、压缩、底色变化或文字遮挡。
- 对照资料可支持建立首版 `MARD -> COCO` 映射库，但正式使用前应整理为结构化数据并人工核对。

因此，首版将“色号文字”作为高价值识别证据，同时使用格子取色降低 OCR 受水印和模糊影响时的错误率。

## 3. 已确认范围

### 3.1 首版包含

- Windows 本机运行、通过浏览器访问的本地网页应用。
- 图片输入格式：`JPG`、`PNG`、`WebP`。
- 来源标准默认且首要支持 `MARD`，目标标准默认且首要支持 `COCO`。
- 对未标明品牌标准的上传图，界面默认按 `MARD` 处理，但允许用户在识别前修改来源标准。
- 处理规则网格、存在可读来源色号的电子图纸。
- 结合 OCR 与格子底色取样识别来源色号。
- 对识别不可靠、映射冲突或无可靠映射的项目提供推荐，并支持人工修改。
- 导出转换清单、目标标准干净图纸与原图叠加检查图。
- 保存结构化、可再次打开的项目数据。

### 3.2 首版不包含

- 实物拼豆照片的豆子检测或颜色识别。
- 没有色号文字的普通像素画自动转图纸。
- 不带规则网格的插画或照片自动切格。
- Excel 导入导出。
- 云端存储、在线分享、多用户协作。
- 全品牌完整映射支持。

### 3.3 未来扩展

- 在识别结果上直接使用画笔或填充工具编辑格子。
- 批量替换图纸中的某种颜色。
- 从零创建图纸或导入 Excel。
- 扩充品牌色卡与品牌间映射。
- 在可控条件下支持仅有色块的规则像素图。

## 4. 产品方案

采用“结构化、半自动转换”方案：系统不是直接修改原图片上的文字，而是先把图片转换成可编辑图纸模型，再由模型生成清单与输出图。

该方案的原因：

- 校对可以定位到具体格子与具体映射，不必反复处理整张图片。
- OCR 与取色可以共同参与判断，适用于带轻度水印或文字不清的样例。
- 输出图可以采用清晰一致的版式，不被原图水印和压缩质量限制。
- 后续编辑器功能可以直接建立在同一个数据模型上。

对于系统无法可靠判断的内容，首版提供人工校对兜底，而不是追求对所有网络图纸全自动成功。

## 5. 用户流程

```text
上传图纸图片
-> 选择/确认来源标准 MARD 与目标标准 COCO
-> 自动检测网格范围与行列
-> OCR + 格子取色识别来源色号
-> 使用已核对映射库转换为目标色号
-> 查看左右图纸对照与待确认列表
-> 人工确认或修改疑点
-> 保存可编辑项目
-> 导出 COCO 图纸、叠加检查图、转换清单
```

## 6. 混合识别设计

### 6.1 网格检测

系统首先尝试识别外部图纸边界、规则网格线和行列数，形成每个格子的空间范围。图片未能检测出规则网格时，不继续自动转换，而是提示当前图片超出首版可靠处理范围。

### 6.2 每格证据

对每个候选豆子格，提取以下信息：

- OCR 文字候选：例如 `H7`、`D5`、`F14`。
- 格子底色采样值：从避开网格线与文字笔画的区域计算代表颜色。
- 图例辅助信息：若图片带有色号图例，可使用图例中的色号和色块作为本图局部参考。
- 遮挡/异常信息：水印覆盖、模糊、格线偏移或颜色不均匀。

### 6.3 判断规则

- OCR 结果属于已知 `MARD` 色号且底色与候选一致时，自动确认来源色号。
- OCR 无法可靠识别，但格子颜色与本图已确认图例或已确认同色格高度匹配时，提供来源色号推荐并降低置信度。
- OCR 与颜色证据冲突、多个颜色候选接近或存在遮挡时，将格子列入待确认。
- 颜色允许存在一定色差，用于辅助确认和候选排序；网络图片的压缩、滤镜及水印意味着颜色不能在首版独自成为最终依据。

### 6.4 映射规则

- 经过人工核对的唯一 `MARD -> COCO` 映射可以自动应用。
- 映射缺失或多份资料存在冲突时，系统基于颜色接近度推荐 `COCO` 候选并标记为待确认。
- 用户确认某一来源色号的目标映射后，默认应用到该图纸内所有相同来源色号格子，并允许后续单格覆盖。

## 7. 界面设计

应用采用适合 Windows 浏览器窗口的桌面网页布局，而非特定移动端或 iOS 外观。

### 7.1 上传与参数区

- 上传原始图纸图片并显示缩略图。
- 选择来源标准和目标标准，首版默认 `MARD -> COCO`。
- 显示自动检测出的网格行列，例如 `50 x 48`。
- 显示处理状态和识别质量提示。

### 7.2 图纸校对工作区

- 左侧为原图及识别叠加视图，可切换网格线、OCR 标注与低置信度高亮。
- 右侧为按目标色号重绘的干净图纸预览。
- 点击格子后可查看并修改坐标、取样色、来源色号候选、已确认来源色号、目标色号、置信度及异常原因。
- 待确认格子在两侧视图中同步高亮。

### 7.3 待确认列表

- 列出 OCR 与取色冲突、无唯一映射、水印遮挡和无法识别等事项。
- 优先按“色号映射”集中处理，例如一次确认 `MARD H7 -> COCO B09`。
- 支持必要时逐格修改，解决局部识别异常。
- 未完成关键疑点确认时可预览，但导出时明确提示仍存在未确认项。

### 7.4 统计与导出区

- 显示来源与目标颜色的色号、色块及数量统计。
- 导出干净重绘图。
- 导出原图叠加检查图。
- 导出转换清单，首版采用便于查看和后续处理的 `CSV` 格式。
- 保存和重新打开本地项目文件。
- 项目中记录原始图片来源说明；用户导出或分享重绘图时，界面提醒保留原作者出处与遵守原图使用许可。

## 8. 技术架构

首版采用本地前端界面与本地图像处理服务组合：

```text
浏览器界面
  | 上传、校对、导出、项目管理
本地应用服务
  | 项目读写、任务编排、输出生成
图像处理模块
  | 网格检测、OCR、格子取色、叠加图与重绘图
颜色标准库
  | 标准色号、展示色值、品牌映射与版本
项目数据文件
  | 原图引用、网格、格子结果、人工修正、导出记录
```

首版完全本地运行，不需要将用户图纸上传到远程服务器。

### 8.1 色卡与映射数据来源

用户收集的色卡图片是建立映射库的原始依据，而不是运行时每次临时 OCR 的数据源。开发阶段应将 `MARD`、`COCO` 的色号与映射关系整理为结构化数据，并人工核对一次后赋予版本号。运行时转换应记录使用的映射库版本，以保证历史项目可复现。

## 9. 数据模型

项目应以结构化数据保存，以支持首版校对以及后续编辑。概念模型如下：

```text
Project
  id
  name
  sourceImage
  sourceStandard: MARD
  targetStandard: COCO
  paletteVersion
  grid
    rows
    columns
    bounds
    cellGeometry
  mappings[]
    sourceCode
    targetCode
    origin: verified | recommended | user-confirmed
    confidence
  cells[]
    row
    column
    occupancy
    sampledColor
    ocrCandidates[]
    detectedSourceCode
    confirmedSourceCode
    targetCode
    confidence
    status: confirmed | review-required | empty
    issueReasons[]
  exportHistory[]
```

项目文件可采用自描述的本地格式，例如扩展名 `.beadproject`，内部内容可演进并包含格式版本号。具体序列化格式在实施计划阶段确定。

## 10. 异常处理原则

- **网格检测失败**：停止自动转换，提示图片类型或质量不满足首版要求。
- **图片过小或模糊**：识别前显示质量风险提示，允许用户继续尝试。
- **OCR 与颜色冲突**：显示候选和依据，等待用户确认，不静默定案。
- **映射缺失或冲突**：推荐近似目标色号并要求用户确认。
- **水印遮挡**：在叠加检查视图中高亮受影响格子，并纳入待确认列表。
- **仍有疑点时导出**：允许用户明确选择带风险导出，同时在清单或输出状态中记录未确认项目。

## 11. 首版验收标准

- 4 张现有样例图片均能上传并进入识别或可解释的校对流程。
- 对无严重遮挡的规则网格样例，系统能够识别网格和主要来源色号，并自动生成 `COCO` 初稿。
- 对带水印样例，系统能标出不确定区域并允许人工修正，不以全自动无错误为验收条件。
- 用户可以处理映射推荐与识别疑点，生成数量统计正确的目标转换清单。
- 校对完成后可以导出可实际用于拼豆操作的干净 `COCO` 网格图纸以及原图叠加检查图。
- 项目结果可以保存并重新打开，用户修改不会要求从原图重新识别开始。

## 12. 实施前待办

以下工作属于实施计划而非需求再扩张：

- 选择本地网页应用技术栈和 OCR/图像处理实现路径。
- 将现有对照图片整理并人工核对为首版结构化映射库。
- 针对 4 张样例定义可衡量的识别测试用例。
- 设计项目文件格式、导出图片版式和转换清单字段。
