# 桌面软件式工作台 UI 改版设计

## 1. 目标

把当前浏览器里的拼豆图纸转换页面改成更像独立桌面软件的工作台界面，同时继续运行在现有 React + FastAPI 浏览器架构上。

这次改版不引入 Electron、pywebview、Tauri 或原生 GUI，不改变识别算法、项目格式、导出格式和打包方式。目标是让当前浏览器版看起来和用起来都接近未来独立软件窗口，并让后续窗口壳复用这套前端。

## 2. 设计原则

- 首屏就是可用工作台，不做网页式宣传页或大标题 hero。
- 信息密度向桌面工具靠拢：更紧凑的工具栏、稳定的左右/侧边布局、更少大圆角和大留白。
- 导入、打开、保存、导出、校对、非拼豆标记都保留现有能力，只重排和收敛入口。
- 前端继续消费现有 API；不把文件操作、窗口操作和浏览器下载行为散落在组件里。
- UI 文案按“本地软件”表达，例如“保存项目”“导出文件”，避免强调浏览器下载。

## 3. 新布局

整体采用四区结构：

```text
顶部命令栏
左侧项目栏 | 中央图纸工作区 | 右侧校对/属性栏
底部状态栏
```

### 3.1 顶部命令栏

顶部命令栏替代当前页面 header。它应包含：

- 应用名称：`拼豆图纸转换工具`。
- 主要命令：导入图片、打开项目、保存项目、导出。
- 次要入口：色卡/设置/帮助可以保留为未来位置，首版只放已有功能入口。

命令栏应保持固定高度，使用更像软件工具栏的按钮尺寸。导入和打开项目可以继续由隐藏的文件 input 驱动，但用户看到的是命令按钮。

### 3.2 左侧项目栏

左侧项目栏负责“项目和输入状态”，包括：

- 上传图纸入口和缩略预览。
- 来源/目标标准，当前仍固定为 `MARD -> COCO`。
- 识别按钮与识别进度。
- 识别耗时诊断摘要和详细指标。
- 网格尺寸、项目出处记录。

未加载项目时，左侧项目栏是清晰的开始入口。加载项目后，它变成项目状态面板，不抢占中央图纸空间。

### 3.3 中央图纸工作区

中央区域是主工作区，占据最大空间。它包含：

- 左侧：原图识别叠加视图。
- 右侧：COCO 重绘预览。
- 每个预览有独立缩放、重置、叠加开关。
- 全屏校对仍保留，但样式应更像“专注模式”，不是单纯拉大网页卡片。

预览区域应减少卡片感，使用清晰边框、紧凑标题行和固定工具行。图纸区域需要有稳定尺寸，避免按钮、标签或色数条导致布局跳动。

### 3.4 右侧校对/属性栏

右侧栏集中承载校对操作，避免操作分散。建议采用两个或三个分区：

- `校对队列`：待确认分组、定位、确认、修改候选。
- `选中格`：当前格坐标、来源色号、目标色号、状态、问题原因。
- `工具`：标记单格非拼豆、进入/应用/取消框选非拼豆区域。

如果空间不足，可以使用 tabs，但首版优先使用固定分区，降低实现复杂度。

### 3.5 底部状态栏

底部状态栏显示全局状态：

- 当前项目是否已加载。
- 网格尺寸。
- 待确认数量。
- 当前选中格坐标。
- 最近识别耗时摘要。
- 导出风险提示摘要。

状态栏只做信息反馈，不放复杂操作。

## 4. 视觉标准

- 背景使用中性灰或近白，不使用网页式大块渐变或装饰。
- 面板圆角控制在 `6px` 到 `8px`。
- 工具按钮高度稳定，文本短，图标可作为后续增强，但首版不强制引入图标库。
- 标题字号收敛，避免 hero 级大字。
- 颜色以中性色为主，只用一种主强调色表示主要操作和选中状态。
- 预览、队列、状态区域都应有明确边界，但避免卡片套卡片。

## 5. 文件操作边界

为了后续独立软件窗口复用，前端文件动作应逐步收敛到单独边界。首版可以新增或整理一个小模块，例如：

```text
apps/web/src/platform/fileActions.ts
```

该模块先包装现有浏览器行为：

- 选择图片。
- 打开 `.beadproject`。
- 保存导出文件。
- 保存项目文件。

本轮 UI 改版不要求接入原生文件对话框，只要求组件不继续扩散新的下载和文件 input 细节。以后切换到 pywebview 或 Electron 时，可以在这个边界替换实现。

## 6. 非目标

本轮不做：

- 独立软件壳。
- 新增识别算法或 OCR 策略。
- 新增撤销、画笔、填充、批量替换等编辑能力。
- 改变 `.beadproject` 格式。
- 改变导出文件格式。
- 大规模重写前端状态管理。

## 7. 验收标准

- 浏览器中打开后，首屏呈现为工具软件工作台，而不是网页介绍页。
- 导入图片、打开项目、校对、单格非拼豆、框选非拼豆、保存出处和导出入口仍可用。
- 识别后中央图纸区域是主视觉焦点，左右预览有稳定的工具行和尺寸。
- 右侧校对操作集中，用户不需要在多个远离区域之间找确认、修改和非拼豆操作。
- 1024px 宽度下没有明显文本溢出、控件重叠或主操作不可达。
- 前端测试和生产构建通过。

## 8. 实施顺序建议

1. 记录当前 UI 基线截图和前端测试状态。
2. 建立顶层桌面工作台外壳：命令栏、三栏主体、状态栏。
3. 调整左侧项目栏，把上传、打开、识别和诊断组织成项目状态。
4. 调整中央预览工作区，压缩卡片感，稳定工具行和预览尺寸。
5. 整理右侧校对/属性栏，把校对队列、选中格和非拼豆工具集中。
6. 统一视觉样式：圆角、边框、按钮、字号、色彩。
7. 引入最小的文件动作边界，只包装当前浏览器实现。
8. 更新测试并跑 `npm test -- --run` 和 `npm run build`。
